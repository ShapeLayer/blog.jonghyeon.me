데이지 체인은 꽃들의 뿌리가 땅속에서 연결되어있는 모양, 혹은 꽃 왕관 머리장식을 지칭하는 데에서 유래된 이름으로, 여러 개의 장치가 하나의 선을 통해 연결되어있는 구조를 의미한다.  

인터럽트를 사용하는 시스템에서, 인터럽트의 우선순위를 관리하는 방법 중 하나로 데이지 체인이 고려될 수 있다. 일반적으로 인터럽트는 중요도에 따라 다음의 순위를 갖는데:

1. 전원 공급 이상
2. CPU의 하드웨어적 오류
3. 외부 장치의 요청
4. 입출력 요청, 입출력 상태 업데이트(완료, 오류 등)
5. 명령어 오류
6. 프로그램 검사
7. SVC(슈퍼바이저 호출)

데이지 체인은 이 순위를 하드웨어적인 방법으로 구현하는 방법이다.

## 구현

![](/static/posts/2026-10-03-daisy-chain-in-handling-interrupts/daisy-chain.png)  

데이지 체인은 인터럽트를 요청하는 장치들을 서로 직렬로 연결하고, 우선순위가 높은 장치를 이 연결선상의 앞쪽, 낮은 장치를 뒤쪽에 배치한다.  

이렇게 하여 인터럽트 연결선에 참여하는 장치들은 연결선을 타고 들어오는 인터럽트 신호에 대해 조건적으로 CPU 방향으로 신호를 전달한다.  

| 자신의 인터럽트 요청 | 배후(낮은 순위) 장치의 인터럽트 요청 | CPU로 전달 여부 |
| :-: | :-: | :-: |
| 요청 없음 | 요청 없음 | idle |
| 요청 없음 | 요청 있음 | 배후 장치의 요청 전달 |
| 요청 있음 | 요청 없음 | 자신의 요청 전달 |
| 요청 있음 | 요청 있음 | 자신의 요청 전달 |

하지만 낮은 순위 장치의 요청이 무시되었을 때, 그 장치의 요청을 유지시키는 것에 대해서는 데이지 체인 범위 내에서는 고려되지 않는다. C의 요청을 래치해두는 것은 장치 측이나 다른 인터럽트 회로에서 고려되어야 한다.  

## 고려할 점

이 구조는 배후의 장치는 앞쪽의 연결에 의존하므로, 앞 장치의 연결선에 장애가 발생하여 연결이 끊기거나, 앞 장치에서 전달을 승인하지 않으면 배후 장치의 요청은 CPU에 전달되지 않는다. 문제가 발생하지 않더라도 같은 이유로, 앞 장치의 요청이 반복해서 발생하면, 배후 장치는 기아 상태에 빠질 수 있다.
